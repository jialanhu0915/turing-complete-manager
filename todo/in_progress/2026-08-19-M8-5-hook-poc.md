## 技术要点

### inline trampoline（patch size 可配置）

```
[0..N]                  ; N 字节原 prologue（默认 14，可配 31 用于 compile.dll）
[FF 25 00 00 00 00]     ; JMP [RIP+0]   (6 bytes)
[<8-byte absolute>]     ; hook function 地址（紧跟 JMP 指令的 8 字节）
```

- **绝对跳转**跨模块唯一（hook DLL 和 compile.dll 不同模块）
- **`RIP+0` 巧妙**：JMP 指令后 8 字节直接放目标地址，RIP 自然指向
- **patch size 必须 ≥ prologue size**，否则拆指令（14 字节对 compile.dll 拆了 `sub $0x118,%rsp`）

### compile.dll::compile prologue（31 字节，硬编码）

```
2fddec340: 8 个 callee-saved pushes        12字节
2fddec34c: sub $0x118,%rsp                  7字节
2fddec353: movaps %xmm6,0x100(%rsp)        8字节
2fddec35b: pxor %xmm0,%xmm0 (66 前缀)       4字节
──────────────────────────────────────────────────
合计 31 字节（prologue 后是 `mov (%rdx),%rbp`）
```

如果游戏更新改了 prologue，需要重新反汇编确认并更新
`dll.rs::COMPILE_DLL_PROLOGUE_SIZE`。通用化（自动 disassemble 找边界）留待后续。

### trampoline-back（让 hook 调原 compile，游戏继续工作）

```
[0..31]  完整 prologue（原 31 字节）
[31..37] FF 25 00 00 00 00              ; JMP [RIP+0]
[37..45] <8-byte abs of compile+31>    ; 跳回 prologue 后的第一条真指令
```

hook 函数调 trampoline-back 时，传入与原 compile() 同样的 rcx/rdx/r8/r9。
原 prologue 完整执行，JMP 跳回 compile+31（clean boundary），剩下函数继续。
**结果**：游戏保持原行为，hook 同时观察到 pre + post 状态。

### inject 工具（CreateRemoteThread + LoadLibraryW）

```
1. OpenProcess(pid, PROCESS_ALL_ACCESS)
2. VirtualAllocEx + WriteProcessMemory → 把 DLL 路径拷进目标进程
3. GetModuleHandleW("kernel32.dll") + GetProcAddress("LoadLibraryW")
4. CreateRemoteThread(load_library_w, path_ptr) → Windows 自动调 DllMain
5. WaitForSingleObject + 清理
```

## 已知限制

1. **COMPILE_DLL_PROLOGUE_SIZE = 31 是 hard-coded** —— compile.dll 专用
2. **hook 函数不修改 src_str / out_buf** —— 只观察不修改；mod callback API 阶段会加改写能力
4. **AV / Steam 完整性检查 风险未评估** —— DLL injection 通常被 Defender 误报
3. **没有 mod callback API** —— hook 是硬编码的本地函数（`compile_hook`），mod 开发者没法注册自己的回调
5. **不 dump DSL / MC 到磁盘** —— 我们已经在 hook 里读到指针 + 长度，但没把字节写到文件
